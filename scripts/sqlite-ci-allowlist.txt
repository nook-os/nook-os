# ── production decodes a raw uuid that is TEXT on SQLite (MAIN-289) ──
#
# `identity::org_of` reads `tenants.org_id` into a bare `uuid::Uuid`, which wants
# 16 bytes; on SQLite the column is a 36-char TEXT and the decode fails with
# `ParseByteLength { len: 36 }`. Every `AuthCtx::require(..., Scope::Tenant(_))`
# goes through it, so this is the first binary to exercise the permission
# predicate on SQLite at all — the gap is production's, not the test's.
#
# Both binaries here exercise `AuthCtx::require`, which is the only reason they
# are the ones that trip it — any future test of a permission will land in the
# same place until `org_of` is swept.
#
# Worth knowing while it is listed: on SQLite one of its cases passes for the
# WRONG REASON. `somebody_elses_grant_is_not_mine` asserts a refusal, and a
# decode error is also not an Ok — so it would read green against a database
# that never answered the question. That is why the whole binary is excluded
# rather than the two loud cases.
rbac_across_tenants        # org_of decodes a raw uuid; TEXT on SQLite (MAIN-289)
implicit_tenant_admin      # org_of decodes a raw uuid; TEXT on SQLite (MAIN-289)
